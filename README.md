# tubik-privacy

Публічні сторінки застосунку **Tubik** на GitHub Pages:

| Файл | Адреса | Призначення |
|---|---|---|
| `index.html` | <https://airstep.github.io/tubik-privacy/> | політика конфіденційності — Privacy Policy URL в App Store Connect, посилання у формі згоди AdMob, `kPrivacyPolicyUrl` |
| `marketing.html` | <https://airstep.github.io/tubik-privacy/marketing.html> | сторінка застосунку — Marketing URL в App Store Connect |
| `support.html` | <https://airstep.github.io/tubik-privacy/support.html> | підтримка — Support URL в App Store Connect, обов'язковий для сабміту |

## Чому окремий репозиторій

Код Tubik лежить у приватному `airstep/tubik` і публічним не стає. GitHub Pages
для приватного репозиторію потребує платного плану, а політика мусить бути
доступна без авторизації — її відкривають App Review, форма згоди AdMob і
будь-яка людина з екрана оплати. Тому тут самі сторінки й жодного коду.

Маркетингова сторінка живе поруч із тієї ж причини: Marketing URL в App Store
Connect теж має бути публічним, а заводити під один статичний файл окремий
репозиторій і окремий Pages-сайт нема сенсу. Вона **не** може стати
`index.html` — та адреса заморожена (див. нижче).

## Джерело правди

`index.html` — **джерело**, а не копія. У `airstep/tubik` тексту політики більше
немає (`docs/legal/README.md` веде сюди). Дві копії того самого тексту
розходяться першою ж правкою, а розбіжність між заявленим і реальним збором
даних — це те, за що знімають застосунок.

Сторінка самодостатня: один файл, двомовний перемикач (EN / UK) на клієнті,
шрифти з Google Fonts. Збірки немає й не треба.

## URL заморожений

Адреса потрапляє в App Store Connect, у повідомлення про згоду AdMob і в
`kPrivacyPolicyUrl` застосунку. Після першого сабміту змінити її означає
оновити всі три місця й дочекатись нового рев'ю. Перейменування репозиторію
ламає URL.

Якщо колись з'явиться власний домен — чіпляти його як custom domain до цього ж
репозиторію, а стару адресу лишати робочою (GitHub тримає редірект, поки репо
не перейменований).

## Що потребує правки й коли

| Подія | Що міняється |
|---|---|
| перша release-збірка з живим ключем RevenueCat | розділи 2, 4, 11: RevenueCat отримує анонімний id, модель пристрою й чек — «Tubik collects nothing» перестає бути правдою |
| перша збірка з живим AdMob | ті самі розділи: IDFA, рекламні ідентифікатори, «Used to Track You» |
| додавання Sentry (M9) | розділ про діагностику + privacy-мітки в App Store Connect, **до** публікації тієї збірки: мітки не міняються без сабміту |
| реліз у App Store | `marketing.html`: рядок «currently in TestFlight» / «зараз у TestFlight» і посилання на сторінку в сторі |
| перейменування рядків у More | `support.html`: сторінка веде людину по підписах з екрана (`More → Відновити покупки`, `More → Сховище`, `More → Експортувати бібліотеку`). Підпис, якого в застосунку вже немає, — це інструкція в нікуди |

Дата в шапці (`effective`) і `policy version` у футері оновлюються разом із
текстом. Стара редакція лишається в git-історії — цього достатньо.

## Юридичний статус

Текст підготував AI-асистент. Це не юридична консультація. Достатність
залежить від юрисдикції, форми ведення діяльності й ринків релізу — вичитка
юристом на власникові.

Чернетковий банер із попередженням прибраний свідомо: він писався для внутрішньої
роботи й на публічній сторінці читався б як «ми самі не впевнені, що тут
написано».

## Публікація

```bash
git add -A && git commit -m "Update privacy policy" && git push
```

GitHub Pages: Settings → Pages → Source `Deploy from a branch`, гілка `main`,
тека `/ (root)`. Перший деплой — до хвилини, далі кожен push.
